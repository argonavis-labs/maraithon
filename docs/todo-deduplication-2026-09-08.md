# Keep one todo per real obligation

The Runner policy screenshot came from seven open Gmail todos for the same September 2 Comp AI policy-acceptance batch. Each had a different model-generated dedupe key. Intake sometimes recognized multiple copies but could only update one; it could not consolidate the others. The same source message could also surface as a policy-specific task alongside the broader batch.

Intake now compares batches and their covered substeps, retains older completed/dismissed work in related-work retrieval, and can explicitly merge redundant existing IDs into one canonical todo. The model decides meaning and scope; title overlap retrieves context but never authorizes a merge. Different owners, opposing owed-by/owed-to obligations, organizations, policy versions, invoice references and genuinely new occurrences remain distinct. An informational FYI copy can be absorbed into the matching actionable obligation.

Canonical updates and duplicate retirement commit atomically. Original rows retain their evidence and point to the canonical todo. Old dedupe keys and source matches follow those aliases, so replay cannot revive a retired copy. Duplicate consolidation does not produce negative relevance feedback. Matching closed work stays closed.

Models reason outside the database transaction. Intake captures a fingerprint of the work inventory and checks it inside a short per-user write transaction. If another intake changed the work while the model was thinking, the decision is retried once against current context; continuing contention returns to the existing durable retry path. Embedding/provider work remains outside this write lock. Intake refuses to proceed if all existing-work context is lost during prompt fitting.

No schema migration or new coordinator process is introduced. Phoenix compile is the required check; tests remain unchanged and are not run under the current manual-first policy. Production verification uses the actual policy notices and checks that repeated intake retains the same canonical ID and one active obligation.

The first production replay rejected the merge because three of the seven policy copies had been classified as FYI. The transaction rolled back, leaving all seven unchanged. The direction check was refined to distinguish an informational copy from an opposing obligation; the same inconsistency existed in the repeated Shoppers staffing todos.

A larger replay exposed a second failure: all related rows were retrieved, but request fitting silently removed most of them. Related-work IDs are now required context. Intake sheds unrelated recent rows first, then splits oversized source batches into smaller sequential model calls if necessary, preserving the original candidate-index manifest. Each child reads current saved work and commits its own decision batch atomically. A retry of a partially completed source batch reconciles against those saved results.
